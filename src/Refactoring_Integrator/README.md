# Refactoring LLM Benchmark – Module Overview

This module automates the process of applying code refactorings generated by Large Language Models (LLMs) and evaluating their outcomes. It integrates data preparation, project setup, refactoring application, and result storage into a unified workflow.

---

## 📁 Module Workflow

### 1. Data Preparation

All input refactorings are listed in:

```
Data/Data_collection.json
```

Each entry describes a refactoring to attempt using an LLM. The file contains fields such as:

* **ID** – Unique identifier of the refactoring
* **commitID_before** – Commit hash of the project snapshot to refactor
* **Type** – Type of refactoring
* **path_before** – Class path where the refactoring will be applied
* **name** – Method signature to refactor

---

### 2. Refactoring Application (JavaParser)

The system uses a dedicated JAR to apply LLM-generated refactorings:

```
Refactoring_LLM_Benchmark/out/artifacts/RefactoringApplier_jar/RefactoringApplier.jar
```

This tool applies the transformations directly to the target codebase using **JavaParser**.

---

## ⚙️ Required Configuration

Before running the system, update the configuration file:

```
src/utils/config.json
```

### Required fields:

```json
"jdk_path": "Path to your JDK",
"mvn_path": "Path to your Maven executable",
"target_projects": {
    "project_name": {
        "remote_repository_url": "Repository URL",
        "local_repository_path": "Local clone path",
        "initial_commit_version": "Reference commit hash"
    }
}
```

➡️ Add one entry per project you want to benchmark.

---

## 🚀 Running the Module

Once the configuration is set, the module processes each refactoring, queries the LLMs, and injects the generated code back into the corresponding classes.

Running the main entry point launches the entire workflow end-to-end.

---

## 📊 Results

All outputs are stored in:

```
Refactoring_LLM_Benchmark/src/results/
```

Each LLM has its own folder, and each refactoring is executed **five times**. Every execution is stored separately.

Example result path for **DeepSeek – Run 1**:

```
src/results/DeepSeek/run#1/
```

Each folder contains the LLM output, applied patches, logs, and any diagnostics generated during processing.
